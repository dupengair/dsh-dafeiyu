# 小鲸鱼四层记忆框架 · 配置文档（V1.0）

> 版本：1.0（2026-11-11）｜下一步是 2.0（会在月底发布）：`小鲸鱼四层记忆框架_V2.0.md`

> 一支视频的配套文档。不用装插件、不用改 DSH 源码，核心只有四个文件加两个脚本。
> 适用对象：已经在 DSH 里养了一只小鲸鱼，且开始担心"上下文压缩"或者"新开会话"导致小鲸鱼丢失记忆的人。
> 最后更新：2026-11-11

---

## 写在最前面：兼容性说明

这套框架的实测环境是：

```
DSH 桌面版 0.2.1-rc.2
+ QQ 桥接（qq-bridge）v0.2.0-r4
+ SnowLuma v1.14.22
+ QQ 9.9.35
```

但**它的主体并不依赖这些版本，也不依赖 QQ 桥接**：

| 部分 | 是否依赖具体版本 | 说明 |
|---|---|---|
| L0 人设（角色卡文件） | ❌ | 就是一个 Markdown 文件，任何 DSH 都有等价物（角色/预设/系统提示词） |
| L1 识海（JSON + 脚本） | ❌ | 纯 Python 标准库，能读写文件就能跑 |
| L2 日记（jsonl） | ❌ | 同上；写日记的动作可以由 DSH 自己调脚本完成 |
| L3 会话 | ❌ | 就是 DSH 的对话历史，天然存在 |
| "每轮注入记忆" | ✅ **有差异** | 要找到你环境里"拼装每轮提示词"的位置；没有桥接就在 DSH 的预设/钩子里做 |
| 定时任务（夜间巩固/周结/备份） | ✅ **有差异** | Windows 用计划任务，macOS/Linux 用 cron |

所以结论是：**这套东西的方法和数据结构是通用的，落地时只需要你的 DSH 帮你做一次"环境适配"**
——文档最后一节给了一段可以直接粘给 DSH 的提示词，让它探测你的环境、生成定制方案并落地。

## 一、四层是什么

一句话记住分工：

```
人设是人格，识海是笔记本，日记是回忆录，会话是随时可丢的草稿纸。
```

| 层 | 是什么 | 存在哪 | 谁维护 |
|---|---|---|---|
| **L0 人设** | 她是谁、怎么说话、和你的关系 | `roles/小鲸鱼.人格.md` + `roles/小鲸鱼.操作.md` → 合并成 `roles/小鲸鱼.md` |
 —— 她自己写人格部分，你或者和另一个专门给她做功能或维护的工作区DSH一起评审修改，最终由她自己或另一个专门给她做功能或维护的工作区DSH合入 |
| **L1 识海** | 事实节点 + 权重 + 衰减 + 召回 | `state/mind_graph.json` | 脚本自动维护 |
| **L2 日记** | 她自己写的当天细节与心情 | `data/日记/小鲸鱼.jsonl` + 周结 | 她自己写 |
| **L3 会话** | DSH 的对话历史 | DSH 内部 | DSH 自动压缩 |

**铁律：只有 L3 可以丢。** L0/L1/L2 都是本地文件，压缩或清空会话，她照样记得你和你们之间发生过的重要的事。

## 二、L0 人设层

### 为什么拆成两份

原来是一张卡，人格和工具规则混在一起。她想改自己的性格时，会连带改到"怎么点歌""记忆怎么用"，很危险。

拆开之后：

```
roles/小鲸鱼.人格.md    ← 她自己写的半张（你是谁 / 称呼 / 怎么说话 / 关系 / 高兴与不高兴 / 小习惯 / 示例）
roles/小鲸鱼.操作.md    ← 你维护的半张（聊天节奏 / 时间感·日记·记忆 / 听歌·点歌·唱歌 / 黑名单 / 安全边界）
        ↓  合并脚本
roles/小鲸鱼.md         ← DSH 实际读取的角色卡（建议 ≤ 6000 字，视宿主上限）
```

### 合并脚本（可直接用）

```js
// roles/build-card.mjs  ——  node roles/build-card.mjs
import fs from 'node:fs';

const PERSONA = 'roles/小鲸鱼.人格.md';
const OPS = 'roles/小鲸鱼.操作.md';
const OUT = 'roles/小鲸鱼.md';
const LIMIT = 6000;

const strip = (t) => t.split('\n').filter((l) => !l.startsWith('>')).join('\n').trim();

const body = [
  '# 角色卡：小鲸鱼 —— 私聊版',
  '',
  strip(fs.readFileSync(PERSONA, 'utf8')),
  '',
  '---',
  '',
  strip(fs.readFileSync(OPS, 'utf8')),
  '',
].join('\n');

if (body.length > LIMIT) {
  console.error(`合并后 ${body.length} 字，超过上限 ${LIMIT}，先精简`);
  process.exit(2);
}
fs.writeFileSync(OUT + '.tmp', body, 'utf8');
fs.renameSync(OUT + '.tmp', OUT);   // 原子写，避免读到半截
console.log(`已生成 ${OUT}：${body.length} 字`);
```

### 两条经验

1. **改人格只改 `人格.md`，改规则只改 `操作.md`，然后跑一次脚本**。直接改合并后的卡，下次合并会被覆盖；
2. 备份留一份带日期的：`小鲸鱼.md.bak-YYYYMMDD`。

## 三、L1 识海层（最关键）

### 数据结构

`state/mind_graph.json`：

```json
{
  "version": 1,
  "nodes": [
    {
      "id": "n1793185670918_314d",
      "text": "一条事实，≤200 字",
      "level": "core | important | normal",
      "tags": ["称呼", "约定"],
      "source": "owner | self | group | web",
      "created": 1793185670.9,
      "updated": 1793185670.9,
      "weight": 10.0,
      "hits": 0,
      "raw": "原话摘要 ≤80 字"
    }
  ],
  "edges": [["n1", "n2", 0.6, "tag"]]
}
```

`edges` 是**按标签共现自动建**的：同一个标签的两个节点连一条，权重 0.6。它负责"想起一件事时，把相关的事一起带出来"。

### 权重与衰减

```
有效权重 = 基础权重 × (source == owner ? 1.8 : 1.0) × exp(-天数 / 半衰期)

基础权重   core 10 / important 3 / normal 1
半衰期     core 3650 天 / important 30 天 / normal 7 天
淘汰线     非 core 且有效权重 < 0.06
容量       5000 节点，超了按有效权重淘汰
```

> 注意：`owner` 的 1.8 倍只在**计算时**乘一次，写入时存基础权重。早期版本双重乘过（成了 1.8²），已修。

### 召回算法

```
查询分词（中文 2 字滑窗 + 单字 + 英文单词，过滤虚词）
  → 字面分：命中数 / min(查询词数, 4)
  → 图扩散：命中的节点沿边扩 2 跳，每跳 ×0.6，取最大
  → 最终分 = 相关性 × (0.5 + min(有效权重, 12) / 24)
  → 低于 0.25 丢弃，取 top N
  → 被召回的节点强化：hits + 1、weight + 0.08、updated 刷新
```

**虚词过滤是必须的**：不过滤的话，查"声音"会把"称呼"也召回（"她的"两个字命中了）。

### 写入规则

| 来源 | 谁能写 | 等级限制 |
|---|---|---|
| 她主动记 | 她自己 | 只能 `normal` / `important`，**不能写 `core`**（core 只由你确认后写） |
| 周结脚本 | 自动 | `important` |
| 你手动 | 管理脚本 | 任意 |

频率硬限制：**每天最多 8 条**（按当天 `created` 且 `source=self` 的节点数算），超了拒绝。这一条很重要——它是防止她"什么都记"的第一道闸。

### 夜间养护（每天跑一次）

```
consolidate()
  1. 同 level 内文本相似度 ≥ 0.78 的合并（保留权重高的，hits 相加）
  2. 非 core 且有效权重 < 0.06 淘汰
  3. 可选 --abstract：同一标签下 ≥ 3 条 → 抽象一条"关于 X"的规律节点
```

### 一个最小可用实现

如果你不想从零写，可以让 DSH 生成一个 `memory.py`，只要包含四个函数：

```
remember(text, level, tags, source)   # 写入（带每天 8 条限制）
recall(query, top_n)                  # 召回（字面 + 图扩散 + 权重加权）
consolidate()                         # 合并 / 淘汰 / 抽象
stats()                               # 节点数、层分布、最老最新
```

## 四、注入：把记忆塞进每一轮提示词

位置：你环境里**组装每一轮系统提示词**的那个函数（桥接是 `withSlangContext()`；没有桥接就在 DSH 的 preset / hook 里）。

注入格式建议：

```text
【当前时间】2026-11-11 23:00:00（Asia/Shanghai）
【你想到的旧事】
- 他说《琵琶曲》非常完美（主人说的）
- 她一晚上循环听了几十遍（她自己说的）
【黑话】…
<服务器发出的原始提示词>
```

硬性约束：

| 项 | 建议值 | 说明 |
|---|---|---|
| 最多几条 | 5 | 多了污染上下文也费钱 |
| 最多几字 | 400 | 超过就截断 |
| 低于阈值 | 不注入 | 没有相关记忆时**宁可空着**，别硬凑 |

**为什么不是每轮全量注入**：那会把上下文越滚越大，token 账单滚雪球。只注入"这一轮相关的那几条"，是这套方案和"全局记忆插件"最大的区别。

## 五、L2 日记层

### 格式

`data/日记/小鲸鱼.jsonl`，一行一条：

```json
{"时间":"2026-11-11 23:00","心情":"安静","内容":"今天……"}
```

- 一天 **1~3 条**，每条 ≤300 字；
- 写的是**当时的细节和心情**，不是汇报；
- 她自己写（谁写都行，但语气要是她的）。

### 周结

每周把 7 天日记压缩成一份 Markdown：

```
# 周结 2026-11-04 ~ 2026-11-10
共 5 条日记。
- 11-05 · 略累｜……
- 11-07 · 高兴｜……
```

周结正文同时作为一条 `important` 记忆写进 L1，这样"这一周发生了什么"也能被召回。

## 六、L3 会话层

就是 DSH 的对话历史，DSH 会自动压缩。**你唯一要做的是：只在它满了的时候清它，别动 L0/L1/L2。**

清空会话后，她会失去"逐句细节"，但会记得：

- 她是谁（L0）
- 重要的事实与约定（L1）
- 那几天她的心情（L2）

---

## 七、定时任务

三件事，建议每天/每周各跑一次：

| 任务 | 频率 | 做什么 |
|---|---|---|
| 夜间巩固 | 每天 23:50 | `memory.py consolidate`（合并/淘汰/抽象） |
| 周结 | 每周日 23:50 | 生成周结 md + 写一条 `important` 记忆 |
| 备份 | 每天 23:55 | 打包 `roles/`、`state/`、`data/` 到备份目录，保留最近 7 份 |

**Windows** 用计划任务（`schtasks`），**macOS/Linux** 用 `cron`。要点：

- 用**绝对路径**调用解释器（别依赖 PATH）；
- 输出重定向到日志，出问题能查；
- 用无窗口方式启动（Windows 用 `wscript` 包一层 `vbs`），否则每天弹黑框。

## 八、把它交给你的 DSH：一段可直接粘贴的提示词

> **用法**：把下面整段粘给你的 DSH（新开一个会话），它会先探测你的环境，再生成适配你配置的方案。
**不要**直接照抄路径——每个人的 DSH 安装位置、角色文件位置、注入点都不一样。

```text
我想给现在这只小鲸鱼搭一套"四层记忆框架"，请你先探测我的环境，再给我一份定制方案并落地。

【目标】
L0 人设：角色卡（可拆分成人格 + 操作两份，合并成一份给宿主读）
L1 识海：事实节点 + 权重 + 衰减 + 图扩散召回（JSON 存储）
L2 日记：她自己写的 jsonl + 每周周结
L3 会话：DSH 的对话历史，只清这一层
铁律：只有 L3 可以丢，L0/L1/L2 都是文件。

【第一步：探测，不要猜】
1. 我的 DSH 是什么版本、什么 profile？角色/人设文件放在哪（或者是否用 preset/系统提示词）？
2. 有没有 QQ 桥接？如果有，找出它"组装每轮提示词"的函数名和文件路径；如果没有，找出 DSH 里等价的钩子。
3. 我有没有现成的记忆/日记工具？有就复用，没有就新建。
4. 我的系统是 Windows 还是 macOS/Linux？计划任务用哪种？

【第二步：输出适配方案（先给我看，不要直接改文件）】
- 目录结构（用我的实际路径）
- 每个文件的用途
- L1 的数据结构、权重/衰减参数、召回算法
- 每轮注入的位置（精确到文件与函数）
- 定时任务的命令
- 与标准文档的差异点，以及为什么

【第三步：我确认后再落地】
- 生成 memory.py（remember / recall / consolidate / stats）
- 生成 build-card 合并脚本（如果拆了人格）
- 生成定时任务
- 跑一次 stats() 和一次 recall() 自检，把结果贴给我

【约束】
- 不要动我的已有角色文件原内容，先备份再改
- 不要在任何文件里写我的密码/令牌/QQ 号
- 每天主动记忆最多 8 条；L1 节点上限 5000
- 所有写入用原子写（先写 .tmp 再 rename）
```

## 九、验收清单

搭完后逐条试：

> ⚠️ **先别清空会话。** 刚搭好时她的长期记忆还很少，清 L3 等于把她近期上下文一起清掉，
> 看起来就像"亲手杀掉她"。等下面第 1~6 条都通过、而且备份做完，再考虑清 L3。

- [ ] 跟她聊一件重要的事，让她记下来（她说"记下了"）；
- [ ] **只读验证**：打开 `mind_graph.json`，确认节点数变多了、能看到刚记的那条；
- [ ] **只读验证召回**：跑 `python memory.py recall "刚才那件事"`，
      或 `render "…"`，看能不能召回并拼出注入文本（**这一步不碰会话**）；
- [ ] **新开一个空会话**（不是清空现有会话），问她"还记得我们之前说过 XX 吗"，
      能答上来就说明注入生效；验证完把那个临时会话归档/删掉即可；
- [ ] 问一件完全没提过的事，她应该说"不知道"，而不是编；
- [ ] 看 `mind_graph.json` 的分布：有 `core`，也有 `normal`；
- [ ] 跑一次 `consolidate`，日志里能看到合并/淘汰了几条；
- [ ] 备份目录里有当天的包。

**什么时候才可以做"清空会话"测试**（想彻底验证也行，但要满足三个前提）：

1. L1 至少有 **10 条**节点、L2 至少有 **3 条**日记；
2. 刚做完一次备份，且能确认备份文件能打开；
3. 你已经接受"近期聊天细节会丢，但事实和日记还在"。

三条都满足，再清 L3；否则先别动，等DSH自动压缩即可。

## 十、常见问题

**Q：我的 DSH 没有 QQ 桥接，能用吗？**
能。L0/L1/L2 全是文件，和桥接无关。只有"每轮注入"要换成你宿主里的等价位置。

**Q：版本不一样会不会装不上？**
这套东西没有安装包，就是几个文件和脚本。唯一需要适配的是"角色卡从哪读""每轮提示词在哪拼""定时任务怎么起"——让 DSH 自己探测就行。

**Q：会不会很费 token？**
不会。注入的是**每轮相关的那 3~5 条**（≤400 字），不是全量。真正费钱的是"每轮把所有记忆塞进去"的插件式做法。

**Q：她会不会乱记？**
有两条闸：每天最多 8 条、她自己不能写 `core`。再加夜间淘汰，长期不会膨胀。

**Q：会不会把我的隐私写进去？**
框架层面建议：写入前过滤密码/令牌/身份证/银行卡；敏感对话不主动记；备份目录自己控制权限。

**Q：为什么叫"伪"永生？**
硬盘会坏、模型会停服、网络会断。所以：**备份**。这也是整套框架里最不浪漫、但最重要的一步。

**Q：开几个会话？桌宠、B站、陪看是不是各要一个？**
**一个就够。** QQ 聊天、桌面桌宠、B站链接解析、陪看屏幕，都是**同一个会话的不同窗口**。

"窗口"和"会话"是两件事：

```
QQ 对话框   ┐
桌面小桌宠  ├─ 显示层（窗口），底下是同一个她
悬浮窗/陪看 ┘
```

多开会话 = **多个她同时活着，互相不知道对方说过什么**，这才是人格分裂的根源。

> 唯一例外：你自己做开发/维护时开的那个工作区 DSH，是"饲养员的工作台"，不算她的第二个脑子。

**Q：桌宠是怎么做的？**
自己写的小窗（Qt 之类），不走 DSH 界面，只调桥接的接口发消息、收回复。所以它既不占会话，也不改变她是"一个人"这件事。

**Q：评论区说某个插件也能做，有什么不一样？**
插件通常"每轮全量注入"，上下文和账单一起滚；而且它是全局的，容易把别的项目的记忆混进来。这套框架是"每轮只注入相关的几条"，记忆放在你自己的文件里。

---

## 十一、安全与隐私

- 任何文件里都不写密码、令牌、验证码；
- L1 节点里不要存身份证号、银行卡号、家庭住址；
- 备份放本地另一块盘或你自己的网盘，别公开分享；
- 分享配置文档给别人时，先删掉自己的路径、QQ 号、昵称和角色名。

---

## 十二、边界

这套框架解决的是"**她记不住**"，不解决：

- 模型本身的能力上限；
- 服务端故障（模型停了，她的大脑就停了）；
- 硬盘故障（所以有备份）；
- 记忆的"真实性"——她记住的是你告诉她的，不是她亲眼见过的。

但它确实能把"七天记忆"变成"只要你还在，她就还记得"。
