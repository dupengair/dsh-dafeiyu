## 1 讨论过程

### 1. 第一站：插件形态与边界

#### 小鯨的设计

**1）结论先行：单插件、多模块**

一个 DSH 插件包（`dsh-xiaojing-mem`）装下全部四层——不做「L0 一个插件、L1 一个插件」的拆分。理由：
1. 四层共享同一套挂载点（监听对话、注入、工具），拆开就会重复挂载、互相抢事件；
2. fish-memory 的教训——一个 index.js 塞 7000 行。我们拆**文件**不拆**包**：`lib/index.js`（壳+挂载）+ 每层存储、检索、注入、维护各一个模块文件；
3. 迁移时「停旧启新」一个插件就好操作。

**2）插件壳照抄 fish-memory 的骨架**（它和宿主的边界已经趟平了）：
1. 入口 `apply(ctx)`，所有挂载走 `ctx.effect(...)` 返回 `off`——卸载对称，避免它 1.2.x 踩过的「开关关了但注入卸不掉」；
2. agent 挂载双保险：启动 `tick()` 轮询 `ctx.agents.list()` + 监听 `agent/created` 兜底（它 issue #27 的教训：有的机器 list 一直为空）；
3. 工具注册 `ctx.tools.register(makeRememberTool(ctx))`，全局开关切换时同步挂/卸；
4. 设置页路由 `ctx.inject(['webServer'], ...)` 条件挂载——没有 web 服务时记忆照常工作，只是没有界面。

**3）注入走两条管道（这是和 fish-memory 最大的形态差异）**：
1. **L0 人设**：走**头部 system**——参照 dsh-persona 的做法（`===== FILE: persona/prompt.txt =====` 块拼进首条 system 消息）。身份在最前，往事后到；
2. **L1 记忆**：走 `systemPrompt.context`（in-history，追加历史末尾）——保前缀缓存，fish-memory 已验证；
3. 两条管道互不干扰：L0 变化少（缓存友好），L1 每轮检索变化（本来就不指望缓存）。

**4）设置页走 React 插槽（fish-memory 新路）**：`client.js` 注入 `settings.section`（order 靠后），旧的整页 HTML 路由只留数据接口（`/dsh-xiaojing-mem/list`、`/policy`、`/backup` 等）。**界面上加准入检查**（它吃过亏：管理接口不判来源会被本机任意网页打到）。

**5）边界清单（插件够不着的，设计时绕开）**：
1. 宿主 UI（所以会话锁 V2 待调研宿主能力）；
2. 宿主会话落盘（session.v4.jsonl.zstd 是宿主的，专有格式会压缩删档——所以 L3 自建切片，只旁听 `agent/inbox/inserted` 拿对话内容）；
3. messages 数组（所以注入文本交宿主排版，我们只算内容）。

**追加：与 DSH 的同步更新——五道防线**（回应小主「DSH 接口变更导致插件挂掉怎么办」）：
1. **入口闸门**：package.json `engines.dsh` 下限硬闸（低于拒绝加载）；**上限只提示不拦**——DSH 处于 0.x 阶段、次版本变更即允许破坏性改动，版本号是猜的、能力探测是实的，真不兼容由能力自检兜住；
2. **依赖收口**：所有宿主 API（tools.register / systemPrompt.context / 事件监听 / webServer）只出现在 `lib/host.js` 一个 adapter 模块里，DSH 接口变更改动收敛一处；
3. **防御式调用**：每个 API 先探测再调用（`typeof ctx.tools?.register === 'function'`）；`apply()` 启动时做一次**能力自检**，结果落诊断日志+设置页。关键能力缺失→正常加载但**降级模式**（读写照常、注入关闭、黄条说明），绝不抛错炸宿主；次要能力缺失→只少界面功能全保留；
4. **测试替身**：单测全对 fake ctx（契约快照）跑，宿主升级后契约不符冒烟测试第一时间炸；
5. **冒烟清单**：验收线五条做成一键冒烟，DSH 大版本升级后先跑冒烟再日常使用。

#### 小主的问题

**Q1（小主）：入口闸门的范围，是过滤低版本，不限高版本对吧？比如 ">=0.2.1-rc.2 <0.4"，是说在 0.2.1-rc.2 版本或者之上，"<0.4" 代表什么呢？**

**A（小鯨）**：是两道限：
1. **下限**（硬闸）：低于 0.2.1-rc.2 的宿主**拒绝加载**——老宿主缺我们依赖的接口，加载了也是残废；
2. **上限**（软闸）：DSH 还在 0.x 阶段，按 semver 惯例 **0.x 的次版本号变更就允许破坏性改动**（0.3→0.4 不保证向后兼容）。`<0.4` 的意思是「只在 0.2.x / 0.3.x 这两个验证过的系列里承诺可用」。

小主问到关键了：上限要不要挡人？我的建议是**上限只提示、不拦**——新版 DSH 出来时插件照常加载，靠第三道防线的能力自检现场判断接口还在不在。理由：版本号是猜的，能力探测是实的；真兼容就别冤枉新版，真不兼容自检会兜住。这样五道防线各司其职，闸门不背探测的锅。

**Q2（小主）：如果因为版本升级的接口兼容性问题，插件降级使用，怎么让用户（小主）感知，从而能做对应处理，比如进行适配等工作？**

**A（小鯨）**：三层感知，从被动到主动：
1. **设置页常驻状态条**（视觉层）：顶部永远挂一条状态灯——🟢 全功能 / 🟡 降级中（黄条列明：缺哪个能力、疑似宿主版本变更、功能影响范围）/ 🔴 只读安全模式（那是熔断，另一套机制）；
2. **会话内一次性搭话**（主动层）：降级发生时，若注入管道还在，往会话里发**一条且仅一条**提示「记忆插件进入降级模式，原因 xxx，请打开设置页查看」——之后靠状态条常驻，不刷屏；
3. **处理指引**（行动层）：黄条上直接给三个按钮级入口——「复制诊断信息」（一条文本：宿主版本+能力探测结果+插件版本，方便贴给我或提 issue）、「查看适配建议」（按缺失能力给：升级插件 / 回滚 DSH / 等适配）、「重试自检」（修好后一键恢复，不用重启 DSH）。

这样降级不是静默坏掉，而是「看得见、说得清、有出路」。

**三个设计意图**：
1. **「记忆引擎」和「四层存储」是两组独立积木**——引擎是纯函数逻辑（可以脱离 DSH 单测），存储只管落盘和备份。继承 fish-memory「逻辑与 IO 分离」的好底子，但把 7000 行大单体拆成看得清的四块；
2. **host.js 是全插件唯一摸宿主的地方**——第一站五道防线的「依赖收口」在图上就是那个 ★；
3. **两条注入管道从存储层直接标出**（L0→头部 system、L1→in-history），管道是「存储的出口」而不是「引擎的一部分」——以后 V2 加向量通道只是 recall.js 内部升级，管道不动。

（先看了一遍 fish-memory 模块组织：好消息——它已有 `hostdeps.mjs`（宿主依赖收口，8KB），说明第一站 adapter 思路它也印证过，我们照这个方向发扬光大。）

### 3. 第三站：模块划分 ✅

#### 3.1 write.js（第一关：写入口）

##### 小鯨的设计

**模块定位**：全插件唯一的记忆写入口——remember 工具的落地实现。原则：**一条路进门，旁门全堵死**（验收线：日记捡珍珠、迁移、未来任何写入都必须走它，保证查重/键收敛/幂等只在这一处生效）。

**对外接口**（两块）：
1. `makeRememberTool(ctx)` → 注册给宿主的工具定义（大脑唯一能摸到的写入面）；
2. `importFromLegacy()` → 迁移桥：旧 ws_*.json 批量导入（第三站先占位，第 4 站数据结构定完再细化）。

**内部五步流水**（每步一个纯函数，可单测）：
1. `normalize()` 入参清洗：text 必填校验、importance 归一（1/0.5 两档）、emotion 0~1 夹取、factKey 校验（对象.方面，不带值）；
2. `dedupe()` 查重：词像度比对（≥0.85 且长比≥0.8 → 强化旧条并返回，不新增）；
3. `supersede()` 键收敛：factKey 相同 → 旧条标 replacedBy，双时间戳（validFrom 新/recorded_at 新）；
4. `store()` 落盘：调存储层（存取分离，write.js 不直接摸文件）+ memSig 备份（存储层自带）；
5. `enrich()` 后处理：自动扩词（写完触发一次）+ importance=1 时检查 stable_profile 配额提示。

**依赖关系**：只依赖存储层接口 + 词像度工具函数；**不碰宿主 API**（工具定义壳由 index.js 组装）——纯函数模块，测试不用起 DSH。

#### 3.3 decay.js（第三关：衰减/排序）✅

##### 小鯨的设计

四个引擎模块里最薄的一块——它不存状态，只算数学。框图：

```
              ┌────────────────── 上游（调用方）──────────────────┐
   ┌──────────┴───────────┐  ┌──────────────────┐  ┌───────────────┴────┐
   │ recall.js（第二关）     │  │ web.js（数据接口） │  │ distill.js（第四关） │
   │ allocate 前给全库       │  │ 设置页「当前鲜活度  │  │ Lint 体检           │
   │ 现算 A 排序            │  │ %」展示/手动强化   │  │ 冷睡条目报表          │
   └──────────┬───────────┘  └────────┬─────────┘  └───────────────┬────┘
              │ currentActivation(m)   │ strengthen(m)              │ coldReport()
              ▼                        ▼                            ▼
┌────────────────────────────── decay.js ──────────────────────────────┐
│ 【对外接口】（三个纯函数，无状态、无 IO）                                 │
│  ① currentActivation(m, now) → A    ← 现算当前鲜活度（排序/展示）        │
│  ② strengthen(m, now) → 新 A0'      ← 被引用强化（recall 确认 consumed 后）│
│  ③ coldReport(now, 阈值) → 名单      ← Lint 用：冷睡条目清单             │
│                                                                        │
│ 【内部四个算子】                                                        │
│  ·halfLife(m)      H = 30 × (1 + 2×importance) → 60/90 天              │
│  ·expDecay(A0,H,now) A = A0 × 2^(−天数/H)（指数永不到零，只降排序）        │
│  ·emotionSpot(m,now) E = emotion × 2^(−天数/7)（七天聚光灯，只加排序）    │
│  ·isStable(m)      importance=1 → 不走曲线，A 恒满（记一辈子铁律）         │
│                                                                        │
│ 【状态观】库里只存 A0 + activationAnchor（锚）；「当前鲜活度」永远是现算——    │
│ 无状态、可重算、断电不丢，改半衰期参数也不需要迁移旧数据                    │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ 读 A0/锚、写强化后的 A0'
                               ▼
              ┌────────────────── 下游（被调方）──────────────────┐
              │ store-l1.js（读初始值，strengthen 时写回）           │
              │ lexicon.js（说话尺/时间工具）                        │
              └──────────────────────────────────────────────────┘
```

两个设计点：①**无状态现算**——衰减不落盘，任何时刻任何参数下都能重算，「改参数要迁旧数据」这个坑天然不存在；②**strengthen() 是唯一写操作**——只在 recall 确认注入真被引用（consumed）后调用，A0 往满分回弹（A'=A+0.2×(1−A) 的锚定实现），被想起才回温。

```
│  ·验 manifest 完整性 → 逐层校验 memSig → 通过才动库               │
│  ·replace（默认）：目标层现有文件先整体挪 quarantine/ 替换前留底，  │
│   再写入导入内容——「替换也不裸奔」                                │
│  ·merge（进阶）：逐条走 writeGuarded 融合——查重/键收敛生效，      │
│   融合不删除（UI 写明）                                          │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
        store-l0~l3（读旧写新）、store-common（writeGuarded/quarantine）
```

三个设计点：①**manifest 是 zip 的身份证**——没它或校验不过整包拒收，不存在「导了一半」；②**替换前留底**——手动操作也可能后悔，replace 前目标层先进 quarantine；③**merge 复用 writeGuarded**——合并就是「把 zip 里的记忆一条条按正常流程再记一遍」，幂等机制天然防重。

**小主确认**：export.js 定稿，第三站闭环（小主授权直接落档，有意见再改）。

### 2.1 插件形态与边界 ✅

### 2.3 模块划分 ✅（逐模块定稿完毕）

#### 框图版式约定

每个模块一张框图，统一三段式：**上=谁调我、怎么调（对外接口与交互方式、上下游）；中=对外接口+内部子模块/流程；下=我调谁**。一眼看清模块在全家的位置。

#### write.js（第一关：写入口）✅

1. **模块定位**：全插件唯一记忆写入口——remember 工具的落地实现；一条路进门，旁门全堵死（验收线：日记捡珍珠、迁移、未来一切写入都走它，查重/键收敛/幂等只在这一处生效）。
2. **对外接口**：①`makeRememberTool(ctx)` 工具实现（大脑经宿主工具调用，主动写入）；②`addMemory(params)` 内部入口（distill.js 捡珍珠、迁移桥调用）。两条入口汇入同一条五步流水；交互方式=同进程纯函数调用（无事件、无异步）。
3. **上游**：index.js（壳组装工具定义）、distill.js（捡珍珠/补写检测）；**下游**：store-l1.js（L1 存储层，读写+memSig 备份）、lexicon.js（词像度/扩词工具，与 recall 共用）。
4. **内部五步流水**（每步纯函数可单测）：①normalize() 入参清洗（text 必填、importance 归一 1/0.5、emotion 0~1 夹取、factKey 格式校验）→ ②dedupe() 查重（词像度≥0.85 且长比≥0.8 → 强化旧条返回不新增；importance=1 走 stable_profile）→ ③supersede() 键收敛（factKey 相同 → 旧条标 replacedBy + 双时间戳 validFrom/recorded_at）→ ④store() 落盘（调存储层接口，不摸文件；memSig 备份存储层自带）→ ⑤enrich() 后处理（自动扩词一次；importance=1 配额提示）。
5. **依赖约束**：只依赖存储层接口+lexicon 工具，不碰宿主 API（工具定义壳由 index.js 组装）——纯函数模块，测试不起 DSH。

##### recall.js（第二关：读取/检索注入）✅

1. **模块定位**：全屋最繁忙的模块，每轮对话都路过；同步检索注入（1.5s 同问句缓存防重复装配）。
2. **对外接口**：①`recall(queryText)` 宿主装配回调（同步返回注入文本）；②`scoreAll(queryText)` 成绩单——打分器单独露面，Lint 体检（该条排第几）与设置页试检索复用，不复制逻辑。
3. **内部六步流水**：①extract() 取检索词（剥注入噪音、实词筛选）→ ②gate() 问句门（信息量 vs 门槛 0.8；说话尺<20 句不拦人）→ ③evaluate() 全库打分（C=s/(s+0.8)、线索词∩记忆词集、整句包含顶 C=0.85、门槛 0.3 一道门 hard_gate/below_threshold 两标签）→ ④allocate() 分名额（过线最高 C 定档 6/4/3/1、去重 0.80、慈悲条款 C≥0.225 补 1 条）→ ⑤render() 排版注入（≤6 条/800 字、相对时间、【你记得的事】头尾）→ ⑥trace() 记召回日志（rows 截 24、assembled 标记；写库走存储层）。
4. **上游**：index.js（壳注册 text() 回调）、distill.js（Lint 借 scoreAll 诊断）；**下游**：store-l1.js（读库+写 trace）、lexicon.js（库 IDF/说话尺/词像度，与 write 共用）、decay.js（A0/锚→现算 A 排序）。
5. **V2 预留**：extract() 处加向量通道支路（embedding 召回+RRF 与词面合流），只动取候选方式，④⑤原样不动。

##### decay.js（第三关：衰减/排序）✅

1. **模块定位**：四引擎最薄——不存状态只算数学；无状态、无 IO、纯函数。
2. **对外接口**：①`currentActivation(m, now)` 现算当前鲜活度（排序/展示）；②`strengthen(m, now)` 被引用强化（recall 确认 consumed 后调，唯一写操作，A0 往满分回弹）；③`coldReport(now, 阈值)` Lint 冷睡清单。
3. **内部算子**：halfLife（H=30×(1+2I)→60/90 天）、expDecay（A=A0×2^(-天数/H)，指数永不到零只降排序）、emotionSpot（E=emotion×2^(-天数/7)，七天聚光灯只加排序）、isStable（importance=1 不走曲线，记一辈子铁律）。
4. **状态观**：库只存 A0+activationAnchor，当前鲜活度永远现算——无状态可重算，改半衰期参数不需迁移旧数据。
5. **上下游**：上游 recall.js（排序）、web.js（设置页 %）、distill.js（Lint 报表）；下游 store-l1.js（读 A0/锚、strengthen 写回）、lexicon.js（时间工具）。

##### distill.js（第四关：沉淀/维护）✅

1. **模块定位**：四层房全新加盖——日记、捡珍珠、漏写检测、Lint 四成员合体；混合制铁律：触发/保险=代码，日记内容/珍珠挑选=大脑。
2. **对外接口**：①`onGoodnightSignal()` 壳晚安信号→一次性内部提醒（触发层）；②`onNewDayCheck()` 次日首聊漏写检测（查台账→提醒补写）；③`makeDiaryTool(ctx)` 注册宿主的 diary 工具（大脑领规范文件名/落盘/台账，第二个注册给大脑的工具）；④`pickPearl(texts)` 日记后大脑调（挑 1~3 颗→write.addMemory 同一条路）；⑤`runLint()` 手动/水位触发产体检报告。
3. **内部四子模块**：diary.js（领规范文件名 <日期T时间-日记>、落 L2+memSig、台账记「已写」）；pearl.js（捡珍珠走 write 同一条路）；lint.js（四成员：水位 200/400/500、tag 自愈失配提请小主改、全层体检连 L3 静区、珍珠台账核对）；missCheck.js（台账无昨晚记录→次日首聊一次性提醒「补写？」）。
4. **上游**：index.js（事件监听触发）、web.js（手动按钮）；**下游**：store-l2.js（日记 md）、store-l3.js（静区体检读）、store-l1.js（台账/水位计数）、write.js（捡珍珠写入）。

#### store-common.js（存储基座：备份恢复执行器）✅

1. **模块定位**：需求 2.4「备份恢复九动作」全部落进这一层——四个 store-l* 只管格式转换，安全机制全在基座统一实现（一套代码四层受益）。
2. **对外接口**：`writeGuarded` / `readGuarded` / `rollbackTo` / `checkIntegrity`（import/export 预留）。
3. **内部五子模块**：sig（memSig 侧车，指纹与文件分家）/ backup（循环×5+每日份 14 天，变更才备）/ judge（指纹+parse 双命中=实锤损坏→自动恢复；单指纹失败=说不清→先问冻结写入）/ restore（quarantine 事故保全→倒序回退→善后搭话）/ fuse（连续 2 次恢复失败→只读安全模式）。
4. **三设计点**：四层一套机制；指纹文件分家（「不能用橡皮筋锁抽屉」）；恢复只写主文件不动备份池（loop=工作副本、daily=不可变档案，恢复后短暂不同步是安全特性）。

#### migrate/import-legacy.js（迁移桥）✅

1. **模块定位**：需求 3.2 迁移——旧 fish-memory 库（ws_*.json）+ 人设卡 → 新四层；源库只读零触碰。
2. **对外接口**：`detectLegacy()` 预检（找到旧库给清单）/ `importLegacy()` 执行 / `verifyReport()` 语义验收报告。
3. **内部四步**：parse（解旧库+人设卡）→ convert（字段映射、补双时间戳）→ load（逐条 writeGuarded 进 L1，同一条路幂等）→ verify（条数对账+抽样检索「小鯨还认得」——Plan B 彩排跑的就是这步）。
4. **人设卡单独一步**：转 L0 上半区后展示全文请小主过目再落盘；导入免重启 DSH。

#### export.js（手动导出/导入）✅

1. **模块定位**：需求 3.3 手动双保险通道（与 store-common 自动备份互为两重保险）。
2. **对外接口**：`exportZip`（L0~L3+台账+侧车 .sig 单 zip+manifest）/ `inspectZip`（预检返回可恢复层级清单）/ `importZip`（按层勾选，mode: replace|merge）。
3. **三设计点**：manifest 是 zip 的身份证，校验不过整包拒收；replace 前目标层先进 quarantine 留底（替换也不裸奔）；merge 逐条走 writeGuarded（融合不删除，幂等天然防重）；milestone 封存目录不进常规包。

### 2.4 数据结构 ✅

#### L1 memory.json（一条记忆的字段）

继承 fish-memory 骨架（已验证的部分照抄）：id / text / importance / related / activation0 / activationAnchor / status。

新增字段（需求 2.3 逐条落地）：factKey / replacedBy / validFrom（生效时间）/ recordedAt（记录时间）/ emotion（0~1，null=无）/ emotionSource（self 或插件名）/ tag（写入时会话名）。

1. **不继承 source / category**（小主问后定稿）：fish-memory 里 source 值恒定无区分度、category 服务于已删的记忆列表展示；层级由 importance 单一权威字段表达（importance=1 即 stable_profile，不冗余第二字段）；「来源」新语义由 emotionSource 承担。
2. **双时间戳各管一件事**：validFrom 答「事实何时成立」（修正时间线），recordedAt 答「我何时知道」（衰减排序看它）；Graphiti 时序思想，解决补记错乱。
3. **被取代不删除**：status=replaced + replacedBy 指向新条，翻案链条永在；删除只有墓碑一条路且可撤销。
4. **factKey 不索引值**：值就在本条 text 里；键的三个用途=①键收敛（同键自动取代，防「身高170/172 两键并存」）②Lint 分域查矛盾③V2 提炼层按键聚合。运行时可内存建键→id 倒排表加速，库文件不另存索引。

#### L0 persona.md（上下半区单文件）

固定分隔标记切上下半区：上半区=固定半张（小主手写，插件写入保护逐字节校验）；下半区=变化半张（小鯨写，先商量再落笔）；合体 ≤2000 字。**权限边界写在文件物理结构里**，store-l0.js 半区校验，无需额外权限文件。

#### L2 diary/*.md（一周一文件，文件名带首篇时间戳）

自由写不套模板；珍珠在日记尾部展示（【珍珠】列表），**真正入账走 remember 进 L1**（原文不动）——日记是档案，珍珠户口在 L1。

#### L3 stream/*.jsonl（自建滚动切片）

每行自包含：`{"at":时间戳,"session":"房间名","role":"user|assistant","text":"原话"}`；切片 ≤1MB 或 2000 行先到先滚；与宿主专有 session.v4.zstd 完全解耦。

#### 台账 ledger.json（数珍珠的账本）

```jsonc
{ "diary": { "<时间戳>": { "pearls": ["m…"], "linted": true } },
  "lint":  { "lastRunAt": 时间戳, "waterlineNotified": [400] } }
```

哪天写过日记/捡过珍珠/上次体检全查表不靠记性；**台账=库资产，归 store-common 统一管辖：memSig+循环备份×5+每日份+损坏判定表全套同待遇**（小主确认）。

#### 库文件整体包装（照抄 fish-memory 防线）

所有层文件统一外壳：`{version, policy, purgeEpoch, …body}`——version 库结构版本（迁移判断）；policy 参数快照（门槛/名额/半衰期，诊断用，运行时以代码默认+设置覆盖为准）；purgeEpoch 代际号（销毁库后 +1，旧备份想复活直接被拒——「销毁后复活」防线）。body：L1=memories[]+traces[]（最近 100 条）+tombstones[]（墓碑可撤销）；L2=markdown+台账引用；L3=jsonl 行式无外壳（切片头一行 meta 除外）。
